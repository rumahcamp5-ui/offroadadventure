# Offroad × Rumah Camp Membership V7 (source-only integration)

**Status: development branch, not installed, not live.** This is the Offroad-owned half of a future shared Membership points bridge. It is NOT a new Offroad dashboard, payment processor, or member-auth service.

## Mandatory business boundary

- **Offroad keeps its own** public booking site, booking Google Sheet, package/Custom prices, DP, settlement, refund handling, operations, staff and future Offroad admin dashboard.
- **Rumah Camp keeps its own** booking site, stock, finance, staff and admin dashboard.
- **Only** verified Member identity/claim, Offroad source booking ID, completed-trip status, verified-payment **boolean**, trip unit count, timestamps and point awards belong to the shared Membership contract.
- **Never** send Offroad prices, rupiah amounts, bank accounts, DP, remaining balances, invoice details, customer name, WhatsApp, or booking notes to the shared Membership Worker. The Apps Script checks money locally and sends only an eligibility event.
- Shared rank policy by starting rank: Bronze **1**, Silver **3**, Gold **4**, Platinum **8** points per verified Offroad unit. Existing stay points stay on the Rumah Camp source ledger. No award is generated by this adapter.

## What's in this branch

- `membership/OffroadMembershipSourceV7.gs` is a **separate manual adapter**. Do **not** overwrite the booking system's existing `Code.gs` or deploy this as the Offroad public booking receiver. Install it as an additional script file in the existing Offroad Apps Script project only after staging approval.
- `tests/offroad-membership-adapter.test.mjs` runs an isolated mock of the adapter, verifying the HMAC signature, exact payload fields, no personal/financial data, idempotency, cancellation revisions, and failure when payment, trip or sheet ID is unverified.
- `.github/workflows/offroad-membership-check.yml` runs those tests in GitHub Actions for development changes.
- Original `index.html` and `index-2.html` are **unchanged**, including checkout, prices, WhatsApp and Google Apps Script booking URL. This branch does not change live GitHub Pages.

## Staging prerequisites: NOT executed

1. Confirm the Offroad booking Sheet has actual columns O `Status Perjalanan`, P `Tanggal Selesai`, Q `Pembayaran Diverifikasi`, with headers in row 5. Do not rename or move existing A:N columns. Only authorized Offroad staff should set O=`SELESAI` after a real trip, P=completion date/time, Q=verified-payment date/time. For a cancelled trip, O=`CANCELLED`.
2. Keep the three **Offroad-owned** bookkeeping fields intact: J = `Lunas/DP`, K = `Sisa`, L = `Jumlah Uang`. The adapter reads these for local verification only; it never writes to them and never sends their values to Membership. Custom accepted prices are valid.
3. Add these **four Script Properties** to the Offroad Apps Script project, never to a public HTML file:
   - `OFFROAD_V7_SPREADSHEET_ID`: ID of **Offroad's** spreadsheet. The adapter uses `SpreadsheetApp.openById`, not active sheet or Rumah Camp sheet.
   - `OFFROAD_V7_SYNC_ENDPOINT`: the approved **staging** Offroad observation intake endpoint, after confirming its actual deployment and origin.
   - `OFFROAD_V7_SOURCE_ID`: unique Offroad source ID shared with the Membership backend, non-secret.
   - `OFFROAD_V7_SYNC_TOKEN`: high-entropy HMAC secret matching the backend's server-side secret. Never check it into GitHub, Apps Script logs or browser.
4. The Membership backend must have a staging database with migrations 0038–0040, the approved Offroad source ID/token configured, and `OFFROAD_SYNC_V7_ENABLED=true` **only on staging**.
5. Authorized Offroad staff can **manually** call `offroadV7SendVerifiedBooking(rowNumber)` after local payment and trip completion are checked. The adapter sends an authenticated observation with **no points issued**. `offroadV7SendCancellation(rowNumber)` sends a new signed cancellation revision; it does not refund money or reverse historical points.
6. A future **separate Offroad admin dashboard** must own staff approval and independent reconciliation. Membership point issuance and ownership claims remain blocked until that dashboard, the secure Owner review, idempotency and refund gates are end-to-end tested.

## Explicitly not supported

No live source connection, no automatic points, no money synchronization, no auto-onEdit trigger, no new booking API, no live user-data migration, and no merge/deploy approval by creating this PR. Never merge both businesses' operational dashboards or finance ledgers.

The separate draft integration branch on the Membership backend is `rumahcamp5-ui/rumahcamp-admin#5`; it also remains unmerged and not deployed.
